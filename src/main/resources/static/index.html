MinIO S3 API — front end demo

A stand-in for the real front end. Every button below sends the same HTTP request a React app would send. Dev profile only.

1 — Register

Always creates a plain USER — the role is not read from the body.

2 — Log in

The role comes from the database row, never from the request.

Token held by this page

Logging out only clears localStorage — the server stores nothing.

3 — Protected resources

The second one needs ADMIN or MODERATOR. Log in as a USER to see 403.

4 — Files

A USER sees only their own files, a MODERATOR sees every one. Somebody else's file answers 404 rather than 403, so no id can be confirmed to exist. PUT and DELETE are closed to a plain USER by role, so those answer 403.

5 — Events

Nothing here needs to be pressed for the trail to fill up — uploading a file in card 4 already wrote a CREATED entry. POST is ADMIN only and exists because the specification asks for full CRUD.
